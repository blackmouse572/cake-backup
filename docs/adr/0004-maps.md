# Maps: MapLibre for every map, Goong for search and routing in Vietnam, all behind our API

Planning a journey needs place search, a route and an arrival estimate. The safety circle needs a map that shows the traveller's dot and the destination. Whatever we pick decides cost, how well Vietnamese addresses are found, and which companies learn where travellers are going.

Today both apps use stand-ins: the circle website draws OpenFreeMap tiles with MapLibre (`apps/web/src/components/journey-map.tsx`) and the app looks addresses up with the phone's own geocoder (`expo-location`'s `geocodeAsync` in `apps/mobile/src/services/places.service.ts`). Neither gives suggestions while typing, a route or an arrival time.

## Decision

Jaden chose this option on 2026-11-07. The ADR moves to accepted once the address test scores below are filled in.

Split the job in two, and keep the provider behind our own API so it can change without an app release.

- **Drawing the map: MapLibre everywhere.** `maplibre-gl` on the website (already there) and `@maplibre/maplibre-react-native` in the app, with one vector style. Tiles come from OpenFreeMap for now. Before the pilot we host our own tiles as a Protomaps PMTiles file in R2, so tile requests, which reveal the area someone is looking at, stay on Cloudflare with the rest of our data.
- **Place search and routing: Goong** (goong.io), a Vietnamese provider. It is built on Vietnamese address data, has autocomplete in Vietnamese, routes for motorbikes (`vehicle=bike`), and processes queries in Vietnam.
- **The app and the website never call Goong directly.** The API gets three routes, `GET /places/suggest`, `GET /places/:id` and `POST /routes`, and a `MapsProvider` interface with one Goong implementation. The key stays on the server, requests carry no user identity, and a second provider (for trips outside Vietnam) slots in behind the same interface.
- **Outside Vietnam** (Cambodia, Laos, the China border) is not solved by Goong. For the pilot the traveller can still drop a pin on the map; the second provider is picked when the pilot shows how often trips cross a border (see "Open questions").

```text
app / website
  GET /places/suggest?q=…&near=lat,lng      -> [{ id, name, address }]
  GET /places/:id                           -> { name, address, lat, lng }
  POST /routes { from, to, mode }           -> { distanceM, durationS, polyline }
api
  MapsProvider
    goong   (Vietnam)
    later: a second provider for other countries
```

## Criteria

| | Goong | Mapbox | Google Maps Platform | OpenStreetMap stack |
| --- | --- | --- | --- | --- |
| Vietnamese address search | Strongest: Vietnamese data, house numbers, Vietnamese autocomplete | Weaker on house numbers and alleys (hẻm, ngõ) | Strong, good POIs | Weakest: few house numbers in OSM for Vietnam |
| New addresses after the July 2025 merger (34 provinces, no districts) | To test | To test | To test | Depends on OSM editors |
| Motorbike routing | Yes (`bike`) | No (car, walking, cycling) | Yes (`TWO_WHEELER` in the Routes API) | Yes with Valhalla (`motor_scooter`), self-hosted |
| React Native and web | Mapbox GL style, works with MapLibre on both | Own SDKs (`@rnmapbox/maps`, `mapbox-gl`) | Own SDKs; no MapLibre | MapLibre on both |
| Where queries are processed | Vietnam | United States | United States | Wherever we host it |
| Use abroad | Vietnam only | Global | Global (not in mainland China) | Global, quality varies |
| Price at pilot scale | Free tier, then VND pricing (to confirm) | Free tier, then per request and per mobile user (to confirm) | Monthly free calls per API since March 2025, then the dearest of the four (to confirm) | Tiles free; search and routing cost servers and upkeep |
| Lock-in | Low behind our API | Medium (SDK, terms) | High (results must be shown on a Google map under some terms) | None |

Prices change often, so they are checked on each provider's page before the pilot, not copied here.

## Considered options

- **Google Maps Platform for everything.** The best global coverage and good Vietnamese POIs, but the dearest at scale, queries go to the United States, its SDKs don't use MapLibre, and some terms tie results to a Google map. Still the likeliest second provider for trips abroad.
- **Mapbox for everything.** One vendor for tiles, search and routing, with good SDKs. But no motorbike routing, weaker Vietnamese addresses, and per-user pricing on mobile.
- **OpenStreetMap only** (MapLibre, Nominatim or Photon, Valhalla). No vendor and full control of the data. But Vietnamese house numbers are thin in OSM, the public Nominatim forbids autocomplete, and running search and routing servers is work we don't need during a hackathon.
- **Keep the phone's geocoder.** Free and already wired, but no suggestions while typing, no route, different results on iOS and Android, and Apple or Google still sees the query.

## Consequences

- Jaden needs a Goong account and two keys (one for the REST API, one for tiles if we ever use Goong's tiles). The REST key becomes an API secret, `GOONG_API_KEY`.
- The API gains `/places` and `/routes`, rate limited per session, and a `MapsProvider` interface. The app's `places.service.ts` calls those routes instead of `expo-location`.
- The app adds `@maplibre/maplibre-react-native`, a native module, so it needs a new development build.
- Routes from Goong give the planned duration, which feeds the arrival timer (PRD, "The server's job").
- Searches are not stored; only the chosen destination is saved with the journey, as today.

## Open questions

- Which provider for trips that leave Vietnam, and do we need it for the pilot (the field test, #33, will tell).
- Goong's terms on caching and on showing its results on a non-Goong map.
- Whether self-hosted tiles in R2 are worth it before the pilot, or OpenFreeMap is enough.
